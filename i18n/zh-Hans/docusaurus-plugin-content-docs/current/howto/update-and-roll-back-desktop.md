# 更新桌面端，以及退回上一版

从 0.191.0 起，macOS 上的 udctl 桌面端可以自己更新：在应用内下载新版本，重启时安装。本页说明更新怎么进行、更新前的数据副本放在哪里，以及更新出问题时怎么退回上一版。

Windows 和 Linux 上，应用仍然打开[下载页](https://udctl.com/download)，由你手动安装新版本。等各平台验证通过后会再开启应用内更新。

## 更新怎么进行

1. 点击标题栏的**检查更新**，或打开**设置 > 软件更新**。应用只在你点击时检查，不会在后台或启动时检查。
2. 有新版本时点击它。下载在应用内进行，显示真实进度。可以关掉窗口，下载会继续。
3. 下载完成后显示**重启以更新**。你点击之前不会安装。如果有工作区会话正在运行，应用会先告诉你重启将中断几个会话，并请你确认。
4. 应用关闭、替换自身，然后以新版本重新打开。这一步最长可能需要一分钟。

如果已经下载了更新但没有重启，下次退出应用时会安装。

检查和下载不会发送任何账号、设备或使用信息。应用只读取一个版本文件并下载安装包。

应用内更新要求应用位于**应用程序**文件夹。如果从别的位置运行（例如直接在磁盘映像里打开），按钮会改为打开下载页。

设置里的**前往官网手动下载**在任何状态下都可以打开下载页。

## 每次更新前的数据副本

更新可能改变数据库的格式，而旧版本读不了新格式。所以安装之前，应用会把数据库复制到数据目录下名为 `update-backups` 的文件夹：

```
<数据目录>/update-backups/undercontrol-20261120-193045-from-v0.190.0.db
```

- 文件名里有复制的日期时间，以及它来自哪个版本。
- 保留最近的两份。每份和你的数据库一样大。
- 如果复制不成功（磁盘已满、文件夹不可写），更新**不会**安装，应用重新打开后会告诉你原因。

macOS 上的数据目录是 `~/Library/Application Support/undercontrol-desktop`，除非你在设置里选了别的文件夹。

副本只包含数据库。上传的文件不会被更新改动，也不会被复制。

## 退回上一版

只在新版本确实用不了时这样做。更新**之后**新建的内容不在副本里，退回后不会存在。

1. **退出 udctl。** 确认它完全关闭，而不只是关了窗口。
2. **拿到上一版。** 安装包地址是：

   ```
   https://dl.udctl.com/releases/<版本号>/undercontrol-desktop-<版本号>-arm64.dmg    (Apple 芯片)
   https://dl.udctl.com/releases/<版本号>/undercontrol-desktop-<版本号>-x64.dmg      (Intel)
   ```

   把 `<版本号>` 换成副本文件名里的版本，例如 `0.190.0`。线上只保留最新的两个版本。如果你的版本已经不在，就停在这里：没有上一版的安装包，这个步骤做不完，而你现在的数据没有被动过。
3. **安装它：**拖进应用程序文件夹，替换掉新版。先不要打开。
4. **把副本放回去。** 在数据目录里：
   - 把 `undercontrol.db` 改名为 `undercontrol.db.after-update`（确认没问题之前先留着），
   - 把 `update-backups` 里的那份复制到旁边，并命名为 `undercontrol.db`。
   - 如果 `update-backups` 里的副本旁边有一个以 `-journal` 结尾的同名文件，也一起复制过来，命名为 `undercontrol.db-journal`。
5. **打开 udctl。** 它会以上一版启动，数据是更新之前的样子。

下次检查更新时，应用仍会提示有新版本。在修复版本发布之前先不要更新。
